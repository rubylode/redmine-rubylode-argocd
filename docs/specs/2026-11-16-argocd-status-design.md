# Rubylode Argo CD: design

Date: 2026-11-16. Status: approved for planning.

## Intent

Show the state of the applications one or more Argo CD servers manage inside Redmine: which apps are healthy, which
are out of sync with git, and, for an app in trouble, which of its resources are failing and why. Two audiences: a team
that wants a glance in Redmine without opening the Argo CD UI or `kubectl`, and anyone who installs it as a public
Rubylode plugin next to Rubylode Beszel, Uptime Kuma, GlitchTip and Windmill.

A sibling plugin for the cluster itself (nodes, pods, CPU and memory through the Kubernetes API and metrics-server)
is planned as a separate project, `redmine-rubylode-k8s`, after this one ships.

## Goals

- A table of applications per Argo CD instance: name (linked to the app in the Argo CD UI), project, health, sync,
  when it last synced, and the short revision it runs.
- Under an app that is not Healthy, the resources that are failing, each with kind, name and Argo CD's health message
  (for example `Pod billing-api-7d9f… Degraded: back-off restarting failed container`).
- A summary line: "All 12 apps healthy and synced", "2 of 12 need attention".
- Several instances, each with its own address, token and failure state. One instance being down shows "unavailable"
  for that instance only; the others still render.
- The same places to show it as Rubylode Beszel: the wiki macro, a page, a My page block, a partial, the placements
  (welcome page, My page, Overview, paths, top menu) and a widget on the Rubylode Status page when that plugin is
  installed.
- Read only. Tokens stay in environment variables and are sent only to the instance they belong to.

## Non-goals

- Any action: sync, refresh, rollback, delete. The account the plugin uses cannot do them, and the plugin offers none.
- History or charts. It shows the latest state, like Beszel.
- Pod logs, events beyond Argo CD's health message, or resource usage (that is the k8s plugin).
- Argo CD ApplicationSets, Rollouts or notifications as separate concepts. An app generated by an ApplicationSet is just
  an app.

## Anti-goals (a failure even if it works)

- A token reaching a host other than its own instance, appearing in a page, a log line or an error message.
- One slow or broken instance blanking the block, or a page around the block failing.
- One bad deploy flooding Argo CD with requests (see the resource-tree cap).
- Real names from the development cluster (apps, namespaces, hosts, git URLs) in the repository, the fixtures or the
  screenshots.

## Constraints

- Redmine 5.1, 6.0, 6.1 and 7.0; Ruby 3.2 to 4.0 (the same matrix as Beszel). Tests are Minitest.
- Plugin id `redmine_rubylode_argocd`, namespace `RubylodeArgocd`, page `/status/argocd`, macro `{{argocd_status}}`,
  My page block "Argo CD", settings stored as `plugin_redmine_rubylode_argocd`.
- Argo CD 2.x and 3.x. Authentication is a bearer token of a local account that has only the `apiKey` capability and
  `role:readonly`. The README explains how to create one (`accounts.<name>: apiKey` in `argocd-cm`,
  `g, <name>, role:readonly` in `argocd-rbac-cm`, then `argocd account generate-token --account <name>`).
- Argo CD behind TLS-terminating proxies often serves plain http inside the cluster (`server.insecure: true`), so a
  Redmine running in the same cluster reaches it at `http://argocd-server.argocd.svc`. Plain http must be possible
  but off by default, as in Beszel.

## Approaches considered

1. **Copy the house pattern (chosen).** Start from Rubylode Beszel's layout (settings, transport rules, placements,
   macro, page, My page block, Status widget, fake server, demo and screenshot scripts) and borrow Rubylode Windmill's
   API client and attention-rule pieces. Shared helpers (`path_matcher`, `settings_validator`, `status_widget`) are
   copied and renamed, as every sibling does. Matches four published plugins, no dependency between plugins, ships on
   its own. Cost: a fifth copy of the shared helpers.
2. **Extract a `rubylode-core` gem first.** Ends the duplication, but changes and re-releases four published plugins
   before this one can ship. Recorded as a roadmap idea, not done here.
3. **Shell out to the `argocd` CLI.** Rejected: a public plugin cannot require a binary on every Redmine host.

## What was decided

### Data

- Applications: `GET /api/v1/applications` with `Authorization: Bearer <token>`. Ask only for the fields used
  (the `fields` query parameter) to keep the answer small (about a sixth of the full answer, which carries the sync
  history): `items.metadata.name`, `items.metadata.namespace`, `items.spec.project`, `items.spec.sources`,
  `items.status.health`, `items.status.sync.status`, `items.status.sync.revision`,
  `items.status.operationState.finishedAt`, `items.status.resources`.
- `fields` is an allowlist on the server, not a free path filter (checked against Argo CD 3.6.1): `status.health`
  passes only as a whole object (`status.health.status` returns nothing), `status.sync` passes only as `.status` and
  `.revision`, and `status.sync.revisions` never passes. A path not on the list silently drops out.
- Revision: a single-source app shows the short `sync.revision`. A multi-source app has no `sync.revision` and its
  `revisions` cannot be asked for, so it shows the number of sources ("3 sources"), counted from `spec.sources`.
- Failing resources: on Argo CD 2.x, `status.resources` of the same answer carries each managed resource's health.
  On 3.x it does not (resource health lives only in the resource tree), so the managed-resource view has no health
  to show there. For an app that is not Healthy, also `GET /api/v1/applications/<name>/resource-tree` (with
  `appNamespace` when the app is not in the default namespace) to reach pods and their messages. At most 10
  resource-tree calls per instance per refresh; past the cap the app shows the managed-resource view and a note.
- Errors: a bad or missing token returns 401 with `{"error":"no session information","code":16}`. An app that does
  not exist, or one the account may not see, returns 403 `permission denied` (code 7): Argo CD does not say which.
  Argo CD's version is at `GET /api/version` (no `v1`).
- Timeouts: Ruby's HTTP client retries a GET once after a read timeout by default, which doubles the wait and the calls
  to a stuck server. The plugin turns that retry off, so "Timeout seconds 3" means three seconds and one call.
- A row needs attention when health is Degraded, Missing or Unknown, or sync is OutOfSync. Progressing and Suspended
  are shown but do not count. Rows needing attention come first, then by name.

### Settings

| Setting | Default | Meaning |
|---|---|---|
| Instances | empty | One per line: `Name | address | token variable`. The variable must start with `ARGOCD_`. Lines starting with `#` are ignored. The settings page says whether each variable is set. |
| Allow plain http | off | Allows `http://` addresses. |
| Apps to show | empty | One per line: `Instance | app name | label`. Empty: every app each instance has. |
| Cache seconds, Failure cache seconds, Timeout seconds | 60, 30, 3 | Per instance, as in Beszel. |
| Block title | Applications | Heading of the block and the top menu link. |
| Who may see the block | Everyone signed in | Or administrators only. Anonymous never. |
| Show the block on | all off | The placements, as in Beszel. |

A token is sent only to its own instance's host; there is no shared allowed-hosts list, because each line binds a
token to one address. Redirects to another host are not followed with the token.

### Display

```
Applications                                   2 of 12 need attention
Production
App           Project  Health      Sync       Last sync   Revision
billing-api   shop     Degraded    Synced     4 min ago   a1b2c3d
  Pod billing-api-7d9f6c-x2k4p   Degraded   back-off restarting failed container
web           shop     Healthy     OutOfSync  2 h ago     9f8e7d6
...
Staging       Status unavailable (administrators see why)
```

Health and sync use the same colour language as Beszel's bars: green fine, amber Progressing or OutOfSync, red
Degraded or Missing. App names link to `<address>/applications/<namespace>/<name>`. Argo CD 3.6.1's UI router
accepts both that and the older `/applications/<name>`; the namespaced form is the only one that reaches an app outside
the default namespace, so it is the one used. (The development address serves only the API, so this was checked in
Argo CD's UI source rather than in a browser.)

### Development data

A live Argo CD is available for capturing sample answers: `.env` holds 1Password references for
`ARGOCD_DEVELOPMENT_URL` and `ARGOCD_DEVELOPMENT_TOKEN` (read-only token). Raw answers are captured to a scratch folder
outside the repository. Fixtures for the fake server (`test/support/fake_argocd_server.rb`) are built from them with
every app, namespace, host, repository URL, image and revision replaced by made-up values. Include at least one
Degraded app with a resource tree, one OutOfSync app, one multi-source app and one Progressing app.

## Left to the builder

- Exact class layout inside `app/models/rubylode_argocd/` and which Windmill pieces fit as they are.
- Wording of messages and the settings help, following the existing plugins' voice.
- Whether the Status page shows one widget for all instances or one per instance (one for all is the starting point).
- The demo (`bin/demo`) and screenshot script, adapted from Beszel.
- Release mechanics: follow Beszel (CHANGELOG, tag, the release workflow, the redmine.org listing). The repository
  and its remote do not exist yet beyond this folder.
